# Калории EveryDay

Статический трекер калорий: HTML, CSS и JavaScript. Python, сервер API и установка зависимостей не нужны.

**Сайт:** https://kazakbayzhanibek.github.io/calorie_tracker/

## Возможности

- Добавление и удаление продуктов, количество порций и итог за выбранный день.
- Сохранение дневной цели, история последних 14 дней с записями, переключение темы.
- Записи и цель сохраняются в localStorage под ключом `calorie-tracker:data:v1`; тема — под ключом `theme`.
- Изменения отражаются в других открытых вкладках этого сайта.
- Ошибка чтения, заполненное или недоступное хранилище показываются пользователю. Некорректные сохранённые данные автоматически не перезаписываются.

Данные принадлежат конкретному браузеру и адресу сайта. Перезагрузка страницы их сохраняет, но очистка данных сайта удаляет. Между устройствами данные не синхронизируются; приватный режим может удалять их при закрытии.

Старая база `calorie_tracker/calories.db` и файлы прежнего Python-сервера сохранены в репозитории как исходная версия. Новый сайт их не использует и не импортирует автоматически.

## GitHub Pages

В **Settings → Pages** используйте **Deploy from a branch → main → / (root)**. Главная страница — `index.html` в корне репозитория. Все ресурсы подключены относительными путями, поэтому сайт работает по адресу проекта `/calorie_tracker/`.

Файл `.nojekyll` отключает обработку Jekyll. Сборка и собственный GitHub Actions workflow не требуются. Старый адрес `calorie_tracker/static/` перенаправляет на главную.

## Локальная проверка

Для разработки достаточно Node.js 18 или новее, без `npm install`:

```sh
npm test
npm start
```

Откройте http://127.0.0.1:4173/calorie_tracker/ . Проверочный сервер использует только стандартную библиотеку Node.js. На GitHub Pages Node.js не требуется.

Проверяйте страницу через HTTP, а не двойным щелчком по HTML: используются JavaScript-модули.
